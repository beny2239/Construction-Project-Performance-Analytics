# Construction Project Performance Analysis

## 1. Project Objective

This project demonstrates a data analytics workflow for monitoring construction project performance using SQL Server and Power BI.

The analysis combines project schedules, activity progress, costs, materials, labor data, and Earned Value Management (EVM) metrics to evaluate project performance from cost, schedule, productivity, and risk perspectives.

---

## 2. Business Questions

The analysis was designed to answer the following questions:

- Are projects progressing according to plan?
- Which activities are delayed?
- How significant are schedule delays?
- Are actual costs higher or lower than planned costs?
- Which cost categories contribute most to project expenditure?
- Are material quantities aligned with planned quantities?
- How much labor is being used?
- How does labor utilization relate to project progress?
- Are projects performing efficiently from a cost perspective?
- Are projects ahead or behind schedule?
- Which projects require closer monitoring?

---

## 3. Dataset

The project database contains the following tables:

### Projects
Contains project-level information including:

- Project ID
- Project name
- Project type
- Location
- Start date
- Planned end date
- Budget
- Client

### Activities

Contains construction activity information including:

- Activity
- Category
- Building level
- Planned and actual dates
- Planned and actual duration
- Planned and actual cost

### Progress

Contains planned and actual progress measurements over time.

### Costs

Contains cost transactions categorized into:

- Material
- Labor
- Equipment
- Subcontractor
- Other

### Materials

Contains planned and actual material quantities and unit costs.

### Workers

Contains:

- Worker type
- Number of workers
- Working hours
- Labor cost

### DimDate

A dedicated date dimension used for time-based analysis in Power BI.

---

## 4. Data Model

The analytical model follows a relational structure centered around construction projects and activities.

Main relationships include:

- Projects → Activities
- Activities → Progress
- Activities → Costs
- Activities → Materials
- Activities → Workers
- DimDate → Progress
- DimDate → Costs
- DimDate → Materials
- DimDate → Workers

Single-direction relationships were used to maintain predictable filter propagation.

## 20. Business Insights

The dashboard is designed to translate construction project data into actionable management information.

### Cost Performance

Cost variance analysis compares planned and actual expenditure and helps identify projects or activities where spending differs from the baseline.

CPI provides an additional measure of cost efficiency by comparing earned value with actual cost.

### Schedule Performance

Planned versus actual progress and duration analysis helps identify activities that are falling behind schedule.

SPI provides a standardized measure of schedule efficiency and allows project performance to be monitored over time.

### Activity Risk

Activity-level delay analysis can identify construction categories and building levels associated with higher schedule delays.

This allows project teams to investigate potential operational causes rather than relying only on project-level averages.

### Labor Productivity

Labor hours are compared with actual progress to provide an indication of workforce utilization.

Further analysis can be performed by worker type, project, construction category, and time period.

### Material Utilization

Planned and actual material quantities are compared to identify quantity variances.

This can support investigation of material overconsumption, inaccurate planning assumptions, or changes in construction requirements.

### Integrated Project Monitoring

Combining cost, schedule, labor, material, and EVM metrics provides a more comprehensive view of project performance than analyzing each dimension independently.

The dashboard is therefore structured to support both high-level project monitoring and detailed operational investigation.
